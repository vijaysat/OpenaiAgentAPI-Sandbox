## Findings to resolve

### QA-001 — P1: Live analysis cannot complete

A normal user can upload and save holdings, but the fresh valid analysis fails. Reconciliation explicitly says session creation is unconfirmed. No complete root turn, exact successful OCI calculation command, verified valuation, follow-up answer or downloaded report was produced.

The earlier example has a separate startup failure: sandbox `sbx-kehcvzxetauvd3b3` was still CREATING on this test's read-only check. Do not assume that the fresh run has the same cause. Its exact provider response and saved creation request need operator inspection. The existing OCI operator session subsequently could not refresh; no fresh login, replacement session or sandbox was created merely to bypass the uncertainty.

Next verification: reconcile the exact failed creation against provider history, resolve its actual cause, then complete one synthetic analysis and inspect matching root-turn, command, file-integrity and report evidence. Do not clear creation/submission markers or blindly resubmit.

### QA-002 — P1 investigation: Cancelled deletion outcome is not trustworthy yet

The new QA portfolio disappeared after the user reported cancelling the confirmation, and cleanup is pending. This is an observed outcome, not a proven application-code defect: browser dialog handling was interrupted and cannot establish which confirmation result reached the app. The original example was not deleted. Reproduce cancellation manually with a separately agreed disposable portfolio and inspect the request outcome before accepting this flow. Do not mark physical cleanup complete while the banner remains.

### QA-003 — P2: Invalid individual target weights enable Analyze

Reproduce with VTI 101, BND -6, CASH 5 and processing acknowledged. The total is 100%, so the button enables despite invalid per-field bounds. Server validation correctly rejects the request, preventing cloud execution. Add immediate field feedback and disable Analyze unless every target is finite and within 0–100, as well as totaling 100.

### QA-004 — P2: Upload dialog loses keyboard focus on dismissal

Open Import holdings using Enter, then press Escape. The dialog closes, but `document.activeElement` is BODY rather than the opener. Reverse Tab wrapping inside the open dialog works. Preserve the opener before the modal autofocus runs and restore it when closing.

### QA-005 — P2: Failure evidence does not help the user recover

The error asks the user to reconcile, but the Run evidence tab only says session/command/quote evidence appears after completion. The failed run exposes no safe failure stage or support reference in that view. The proposal view also asks the user to run their first analysis after a failed attempt. Show a redacted failure stage and support reference, and explain when operator reconciliation is required instead of presenting a retry loop.
